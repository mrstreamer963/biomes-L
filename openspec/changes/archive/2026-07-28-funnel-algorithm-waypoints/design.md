## Context

Текущая система: A* возвращает `Vec<(u32, u32)>` — путь по клеткам. Каждая клетка конвертируется в центр тайла (`tile_to_pixel`). Waypoint'ы = центры тайлов. Траектория — ломаная линия через центры.

Funnel Algorithm (SSFA) — известный алгоритм для «натягивания струны» через коридор клеток. Результат — waypoint'ы на углах тайлов (вершинах), траектория минимальной длины.

Базовые константы: `TILE_SIZE = 32.0`. Система координат: пиксельная, `f64`. A* работает на grid'е 8-directional с Chebyshev эвристикой.

## Goals / Non-Goals

**Goals:**
- Waypoint'ы располагаются на вершинах тайлов (не в центрах)
- Траектория — кратчайшая через коридор клеток (string-pulled)
- A* остаётся без изменений (только пост-процессинг)
- movement_system без изменений (lerp между `(f64, f64)` уже работает)
- MovementTarget = точная позиция клика, не центр тайла

**Non-Goals:**
- Замена A* на алгоритм непрерывного пространства (Theta* и т.д.)
- Изменение ECS-компонентов (Path, MovementTarget, Position)
- Изменение tile_to_pixel / pixel_to_tile
- Any-angle pathfinding в чистом виде (только пост-процессинг grid-пути)

## Decisions

### Decision: Simple Stupid Funnel Algorithm (SSFA) как пост-процессинг

A* выдаёт `Vec<(u32, u32)>` — последовательность смежных клеток. Для каждой пары смежных клеток извлекаем общее ребро (2 вершины для кардинального хода, 1 для диагонального). SSFA «протягивает» путь через эти порталы.

Псевдокод:
```
1. Построить portals[i] = (left_vertex, right_vertex) 
   для каждой пары cells[i] → cells[i+1]
   portals[0] = (start_pos, start_pos)
   portals[n] = (end_pos, end_pos)

2. SSFA:
   apex = start; left_idx = right_idx = 1
   for i = 2..n:
     tighten left (cross > 0)
     tighten right (cross < 0)
     if crossed (cross(left, right) <= 0):
       add waypoint, reset apex
   waypoints.push(end)
```

**Why:**
- SSFA — стандартное, хорошо изученное решение (Mikko Mononen, recast/detour)
- O(n), минимальные накладные расходы
- Не требует изменений в A*

**Alternatives considered:**
- Theta* — заменяет A*, даёт any-angle пути, но сложнее (нужно переписывать pathfinding, менять алгоритм поиска)
- Простое удаление средней точки (Ramer-Douglas-Peucker) — не гарантирует оптимальность, может выйти за границы проходимой области

### Decision: Порталы для кардинальных и диагональных ходов

Для клеток (c1, r1) → (c2, r2):

| Направление | Левая вершина | Правая вершина |
|---|---|---|
| (1,0) вправо | ((c+1)T, rT) | ((c+1)T, (r+1)T) |
| (-1,0) влево | (cT, (r+1)T) | (cT, rT) |
| (0,1) вниз | ((c+1)T, (r+1)T) | (cT, (r+1)T) |
| (0,-1) вверх | (cT, rT) | ((c+1)T, rT) |
| (±1,±1) диагональ | (угол) | (тот же угол) |

где T = TILE_SIZE = 32.

**Why:** Левая/правая вершина определяется относительно направления движения (вращение вектора движения на ±90°). Для диагоналей обе вершины совпадают (клетки соприкасаются одним углом).

### Decision: MovementTarget = точная позиция клика (x, y)

После прохода SSFA последний waypoint — вершина около целевой клетки. Юнит движется до этой вершины, затем (когда `path.0` пуст) — до `MovementTarget` которым является точный клик `(x, y)`. Финальный отрезок — от последней вершины до кликнутой точки внутри клетки.

**Why:**
- Естественное поведение: юнит останавливается ровно там, куда кликнули
- movement_system уже поддерживает: `path[0]` → пустой путь → `MovementTarget`
- Расстояние финального отрезка < 32 px (в пределах одной клетки)

### Decision: `portal_vertices` — отдельная чистая функция

Не встраивать логику порталов прямо в SSFA. Две функции: `portal_vertices(c1, r1, dc, dr)` возвращает пару `((f64,f64), (f64,f64))`, `funnel_algorithm` использует её.

**Why:** Разделение ответственности, тестируемость, переиспользование.

## Risks / Trade-offs

- **[Границы тайлов]** Юнит идёт по ребру/вершине тайла. При движении впритык к границе (x = 32.0) биом определяется от следующего тайла (floor). Это консистентно с остальным кодом — проблем быть не должно.
- **[Движение сквозь непроходимые тайлы]** Funnel натягивает путь до касания препятствий, но не заходит за них. A* гарантирует проходимость коридора. SSFA не выходит за порталы — безопасно.
- **[Длина пути]** На очень коротких путях (1-2 клетки) SSFA не применяется — waypoints = `[end_pos]`.
- **[Диагональные порталы]** При диагональном ходе обе вершины портала совпадают (точка угла). SSFA корректно обрабатывает нулевые порталы — левая и правая границы схлопываются в точку.
