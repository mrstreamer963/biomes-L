## Context

Сейчас crate `engine` содержит единственную функцию `greet()` — это демо, не игровой код. WebWorker при `init` вызывает `greet()` и отправляет строку в main thread. PixiJS рисует цветной круг. `ideas.md` ставит биомы в основу игры: каждая клетка — биом со своей скоростью прохождения, некоторые непроходимы, и клетка хранит ресурсы. Следующий шаг — первый реальный игровой объект в Rust: сетка биомов с генерацией и доступом через WASM.

Ограничения:
- Crate уже настроен как `cdylib` с `wasm-bindgen`; новых зависимостей желательно не тянуть (особенно `rand` — добавит вес WASM-бандла).
- Worker уже инициализирует WASM-модуль; нужно переиспользовать этот путь.
- main thread не должен блокироваться — сетка живёт в worker'е, отдаётся snapshot'ами.

## Goals / Non-Goals

**Goals:**
- Определить доменные типы биомов, клетки и сетки в Rust.
- Детерминированная генерация карты из `seed` (один seed → одинаковая карта).
- Доступ к данным сетки и клетки через wasm-bindgen API.
- Worker отдаёт snapshot сетки в main thread при `init`.

**Non-Goals:**
- Рендеринг сетки в PixiJS (отдельный change).
- Симуляция tick-loop и движение юнитов (отдельный change).
- Добыча ресурсов — поле есть, но логики нет.
- Сохранение/загрузка карты, редактор карт.
- Множество биомов сверх минимального набора (`Plains`, `Forest`, `Water`, `Mountain`).

## Decisions

### 1. Хранение сетки в Worker, передача snapshot'ами
Сетка живёт в WASM-памяти worker'а. Main thread получает сериализованный snapshot (массив индексов биомов + метаданные), а не дескриптор на живой объект. **Альтернатива**: отдать `JsValue`-дескриптор и дёргать `cell_at` при каждом рендере — но это частые переходы через wasm-boundary. snapshot'ами дешевле для рендера кадра. `cell_at` оставляем для точечных запросов (клик по клетке).

### 2. Генератор без внешнего `rand`
Используем собственный линейный конгруэнтный генератор (LCG) внутри crate'а. Детерминизм важнее «хорошего» распределения; для прототипа достаточно. **Альтернатива**: `rand` + `rand_chacha` — тянет зависимости, разрастает бандл. Откладываем до того, как понадобится качество генерации. Распределение биомов — простое пороговое по значению LCG на клетку (или value-noise-подобная смесь с соседями в будущих change'ах).

### 3. Представление биомов как `repr(u8)` enum
`Biome` — `#[repr(u8)] enum` с вариантами `Plains=0`, `Forest=1`, `Water=2`, `Mountain=3`. Это делает snapshot компактным (`Vec<u8>` индексов) и удобным для передачи в JS как `Uint8Array`. Атрибуты биома (`passable`, `speed_factor`) — в `match`-функции, а не в полях enum'а, чтобы тип оставался plain-данными.

### 4. Snapshot как плоская структура
`grid_snapshot` возвращает объект с `width`, `height` и `biomes: Uint8Array` (длина `width*height`). Это минимально достаточно для рендера и тривиально десериализуется в TS. Координата клетки `(x,y)` → индекс `y*width + x`.

### 5. Ресурсы — поле, но не API
`Cell` содержит `resources: u8` (зарезервировано), но в snapshot и `cell_at` пока не exposed как изменяемое. Добыча — отдельный change. Не вырезаем поле, чтобы не ломать структуру потом.

### 6. Управление памятью
`create_grid` возвращает opaque-дескриптор (идентификатор в `u32`), сетки хранятся в `thread_local` `HashMap<u32, Grid>`. Это избегает передачи ссылок через wasm-boundary. Для прототипа одна сетка, но дизайн допускает несколько. **Альтернатива**: `Box::into_raw` с явным `free_grid` — ручное управление, рискованнее. `HashMap`+дескриптор проще и безопаснее; `free_grid(handle)` добавим, когда станет нужно.

## Risks / Trade-offs

- [LCG даёт слабое распределение] → Для прототипа достаточно; переключение на `rand_chacha` позже не сломает API (seed → map детерминирован, но значения изменятся — примем как новую «версию» карт).
- [HashMap в `thread_local` без очистки] → Утечка при множестве `create_grid`. На этапе прототипа (одна сетка на сессию) допустимо; `free_grid` в Non-Goal, но отмечен для будущего change.
- [Удаление `greet()` ломает demo-поведение] → Это intentional breaking change; worker и Vue-сторона обновляются в рамках того же change, так что демо-приветствие уходит осознанно.
- [Размер snapshot растёт с картой] → `Uint8Array` на 1 байт/клетку; для карт до ~1000×1000 это ~1 МБ, приемлемо. Передача больших карт оптимизируется позже (Region-snapshot'ы).

## Migration Plan

1. Реализовать типы и генератор в Rust, собрать WASM.
2. Обновить `engine.d.ts` (пересобрать типы).
3. Обновить worker: `init` → `create_grid(default seed, width, height)` + `grid_snapshot` → postMessage.
4. Обновить bridge: добавить `grid-snapshot` в `WorkerMessage`.
5. Обновить Vue: `StatusPanel` показывает сводку сетки вместо greeting; composable переименовать.
6. Rollback: git revert change'а возвращает `greet()`-демо; данных пользователя нет, миграция данных не нужна.

## Open Questions

- Нужен ли `cell_at` уже сейчас, или отложить до клика-по-клетке? — Оставить в API (дёшево добавить, полезно для UI).
