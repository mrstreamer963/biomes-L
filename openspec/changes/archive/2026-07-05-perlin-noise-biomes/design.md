## Context

Текущая генерация биомов в `engine/src/ecs/mod.rs` использует LCG-функцию `biome_id_from_lcg_value(v: u32) -> u16`, которая по одному байту случайного значения выбирает биом. Это даёт белый шум — каждая клетка независима от соседей.

Генерация происходит в `wasm_api.rs::create_grid()`: цикл по `y`×`x`, для каждой клетки — вызов LCG → маппинг. Вся карта (сейчас 32×32) генерируется синхронно в WASM при старте. Определения биомов приходят с JS-стороны через `register_biome_definitions()`.

**Ограничения:**
- Отсутствие пространственной когерентности — карта выглядит как случайный шум
- Один слой случайности — невозможно моделировать температуру и влажность
- Нет параметров для настройки генерации (масштаб, тип ландшафта)

## Goals / Non-Goals

**Goals:**
- Заменить LCG-генерацию на многослойный Perlin-шум (FBM) в Rust-движке
- Использовать 2 noise-слоя: температура и влажность → маппинг на биомы
- Добавить параметры генерации: `seed`, `scale`, `octaves` в `create_grid`
- Сохранить полную детерминированность (seed → карта)
- Сохранить обратную совместимость API: `grid_snapshot`, `cell_at` без изменений
- Добавить JS-конфигурацию порогов маппинга noise→biome

**Non-Goals:**
- Бесконечный мир / чанки / streaming — остаётся фиксированная сетка
- Изменение формата snapshot или типов данных на фронтенде
- Редактирование карты после генерации
- 3D-террейн или высоты — только 2D-биомы

## Decisions

### Decision 1: Самописный Perlin noise vs крейт `noise`

**Решение**: Самописный Perlin noise (2D) на Rust.

**Rationale:**
- Perlin noise — простой алгоритм (~100 строк), легко контролировать каждый аспект
- Нет внешней зависимости — меньше размер WASM-биндинга
- Полный контроль над seeding (используем LCG seed для инициализации permutation table)
- Если понадобится Simplex или более сложные шумы — можно расширить позже

**Альтернатива**: крейт `noise` — даёт много алгоритмов из коробки, но добавляет зависимость и увеличивает размер WASM.

### Decision 2: Multi-noise-маппинг (температура + влажность)

**Решение**: Два независимых слоя Perlin noise с разными seed и scale:
- `elevation` (1 слой) — высота местности, определяет воду/горы
- `moisture` (1 слой) — влажность, определяет равнины/лес в пригодной зоне

Маппинг в biome_id:
```
elevation < 0.3 → Water (id=2)
elevation > 0.7 → Mountain (id=3)
иначе:
  moisture > 0.5 → Forest (id=1)
  иначе → Plains (id=0)
```

**Rationale:**
- Два слоя — минимальная модель для осмысленной карты
- Пороговые значения настраиваются с JS-стороны
- Легко расширить до трёх слоёв (температура + влажность + высота)

**Альтернатива**: Один noise-слой с большим количеством октав — не позволяет моделировать разные климатические зоны.

### Decision 3: Параметры генерации как структура

**Решение**: Новый тип `GenerationParams` в Rust, передаваемый из JS:
```rust
struct GenerationParams {
    seed: u64,
    scale: f64,       // базовый масштаб (1.0 = ~1 клетка)
    octaves: u32,     // количество октав для FBM (по умолч. 4)
    elevation_threshold_high: f64,  // порог гор (default 0.7)
    elevation_threshold_low: f64,   // порог воды (default 0.3)
}
```

`create_grid` расширяется: `create_grid(params: GenerationParams, width: u32, height: u32) -> u32`.
JS-сторона передаёт объект, wasm-bindgen десериализует.

**Rationale:**
- Структура проще для расширения, чем позиционные аргументы
- Дефолтные значения на JS-стороне (в biomeConfig или параметрах worker)

### Decision 4: FBM (Fractional Brownian Motion)

**Решение**: Использовать FBM с 4 октавами по умолчанию, persistence = 0.5, lacunarity = 2.0.

```rust
fn fbm(x: f64, y: f64, octaves: u32, seed: i32) -> f64 {
    let mut value = 0.0;
    let mut amplitude = 1.0;
    let mut frequency = scale;
    for _ in 0..octaves {
        value += amplitude * perlin_2d(x * frequency, y * frequency, seed);
        amplitude *= 0.5;
        frequency *= 2.0;
    }
    value
}
```

**Rationale**: FBM — стандартный подход для ландшафтной генерации, даёт естественные детали на разных масштабах.

## Risks / Trade-offs

| Риск | Mitigation |
|------|-----------|
| Производительность: Perlin noise на WASM медленнее LCG | FBM с 4 октавами для 32×32 клеток ~1024 вызова шума — ничтожно. Для 256×256 (65k клеток) — всё ещё <1ms. При необходимости — предрасчёт в lookup table. |
| Качество карты: пороговый маппинг даёт резкие границы | Использовать smooth-интерполяцию между биомами? Пока что резкие границы приемлемы для прототипа. Можно добавить transition zones позже. |
| Размер WASM: самописный noise увеличивает бинарник | Perlin noise — ~200 строк Rust, добавка к WASM < 1KB |
| Детерминизм: разные архитектуры JS/WASM могут давать float-расхождения | Seed → permutation table (int), все вычисления f64 — детерминированы на WASM |
| Обратная совместимость: существующие сохранённые карты | Карты не сохраняются (генерируются заново при старте). Изменение seed даёт новую карту — не проблема. |
