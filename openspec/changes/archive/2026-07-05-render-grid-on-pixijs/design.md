## Context

Текущее состояние: `GameCanvas.vue` инициализирует PixiJS v8 и рисует красный круг по центру. `useGridSnapshot` получает `grid-snapshot` из WASM-воркера (32×32, Uint8Array биомов), но данные не доходят до PixiJS — висит круг-заглушка.

Архитектура данных уже есть:

```
WASM Grid::generate(seed, 32, 32)
  → grid_snapshot() → { width, height, biomes: Uint8Array }
  → Worker → postMessage({ type: "grid-snapshot", ... })
  → useGridSnapshot (reactive)
  → ??? надо замкнуть на GameCanvas
```

## Goals / Non-Goals

**Goals:**
- Отрисовка сетки 32×32 цветных тайлов по данным `grid-snapshot`
- Каждый биом имеет свой цвет (Plains, Forest, Water, Mountain)
- Тонкая сетка между тайлами для читаемости
- Pan канваса (drag мышью)
- Zoom канваса (колесо мыши, с зумингом в курсор)
- Адаптивный размер канваса (как сейчас)
- Код организован в отдельные модули, не в GameCanvas.vue

**Non-Goals:**
- Анимации появления карты
- Туман войны
- Выделение/клик по клеткам
- Спрайты/ассеты (только цветные заливки)
- Частичные обновления карты
- Поддержка карт больше 32×32 (но архитектура должна это выдерживать)

## Decisions

### 1. Рендер тайлов: отдельные PIXI.Graphics на клетку

**Решение:** Каждая клетка — отдельный `Graphics` с `rect().fill()`, сложенный в `Container`.

1024 клетки — легко. Каждый `Graphics` можно независимо подсветить, изменить цвет или удалить. Единый `Graphics` на всю карту сложнее менять по одной клетке.

Для обводки используем `rect().stroke()` — тонкая линия вокруг каждой клетки.

**Альтернативы:**
- *Один Graphics на всю карту* — быстрее, но негибко (придётся перерисовывать всё при изменении одной клетки)
- *PIXI.TilingSprite* — не подходит, у нас нет текстуры
- *Mesh/Geometry batching* — избыточно для 1024 клеток

### 2. Камера: трансформация worldContainer

**Решение:** Все тайлы лежат в `worldContainer = new Container()`. Pan устанавливается через `worldContainer.position`, zoom — через `worldContainer.scale`.

Zoom с привязкой к курсору:
```
новый_scale = clamp(scale * factor, minZoom, maxZoom)
смещение = (позиция_мыши - позиция_контейнера) * (1 - factor)
позиция_контейнера += смещение
```

**Альтернативы:**
- *PIXI.Viewport* — внешняя зависимость, неоправданна для прототипа
- *Просто scale пикселей* — без zoom-to-cursor менее удобно

### 3. Размер тайла: константа TILE_SIZE

**Решение:** `TILE_SIZE = 32` пикселя. Карта 32×32 занимает 1024×1024 пикселя — влазит в экран при scale=1.

При зуме можно уменьшить до ~0.25 (карта целиком) или увеличить до ~3 (разглядеть клетки).

### 4. Цвета биомов

| Биом | Цвет | Шестнадцатеричный |
|------|------|-------------------|
| Plains | Светло-зелёный | `0x7ec850` |
| Forest | Тёмно-зелёный | `0x2d5a27` |
| Water | Синий | `0x3b82f6` |
| Mountain | Серо-коричневый | `0x8b7355` |
| Сетка | Полупрозрачный белый | `0xffffff` alpha 0.1 |

### 5. Подписка на данные

`GameCanvas.vue` вызывает `useGridSnapshot()` на том же уровне, что и инициализацию PixiJS. При получении `grid-snapshot` (watch на `biomes.value`) — передаётся в `MapRenderer.render(biomes, width, height)`.

Если snapshot ещё не пришёл — показываем "Loading..." на канвасе вместо карты.

## Risls / Trade-offs

- **Graphics per cell vs one Graphics**: выбрана гибкость. Если карта вырастет до 200×200 (40k клеток) — можно переключиться на один Graphics или batching без изменения API рендерера
- **Pan/Zoom реализован вручную**: проще и без зависимостей, но potential edge cases с краями карты и multi-touch на мобильных устройствах
- **Нет виртуализации**: все 1024 клетки существуют всегда. Для 32×32 это не проблема, для 200×200 может стать
